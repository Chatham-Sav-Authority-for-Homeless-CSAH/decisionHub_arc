Kiosk Software Comparison

Compass Project — evaluated against ARC project requirements

How these platforms work All four options lock a device to a URL — the kiosk and the partner app read from the same backend automatically if built on a shared API. Single data source and on-demand content updates are solved at the architecture layer, not by the kiosk software. The differentiators are: how well each manages a remote fleet, how much accessibility tooling is built in for public-facing use, and whether the platform is hardware-agnostic.
Push and SMS notifications Kiosk-triggered notifications (e.g. a user requests a caseworker) are handled by the web app running on the kiosk — not by the kiosk software itself. All four platforms are equivalent here. This is an app architecture decision, not a kiosk software decision.
Hardware vendor not yet selected Kiosk hardware procurement happens in Phase 1. Platform support (Windows vs. Android) is noted below — confirm hardware shortlist before finalizing software selection. Note that Esper's Windows support is currently in beta.

Verdict
Summary Solid, mature lockdown platform with the strongest accessibility story via JAWS compatibility — but JAWS is a separate license with significant per-unit cost. Weakest on API-driven data sharing. One-time license is appealing for a grant budget but add KioCloud for remote management and the cost picture changes. No device minimum is an advantage at small scale. Best overall fit for this project. Purpose-built for public-facing web kiosks — not MDM retrofitted. Built-in CMS and strong API align directly with the single-data-source requirement. Touch-first design suits the unhoused user population. Nonprofit pricing at $120/device/yr is the most favorable in this group. 30-day trial de-risks selection before any procurement commitment. No device minimum. Strongest hardware flexibility and best-in-class remote fleet management — the right call if hardware selection lands on a non-standard platform. Renowned for deep kiosk lockdown capabilities. MDM-first means accessibility responsibilities shift entirely to the app layer. Best value per device with no device minimum penalty and NGO pricing available on request. Developer-first platform purpose-built for dedicated device deployments with a strong API and solid kiosk lockdown. Two significant caveats for this project: the 25-device minimum means paying ~$600/year for 3 kiosks (22 unused licenses), and Windows support is currently in beta — a real risk if hardware selection lands on Windows. Best fit if hardware is confirmed Android and the team wants maximum API flexibility. Verify whether nonprofit pricing is available before pursuing.

Scores reflect fit to Compass Project requirements only — not general-purpose rankings.
