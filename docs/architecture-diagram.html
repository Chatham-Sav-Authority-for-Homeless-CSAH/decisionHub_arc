Each Piece, Explained

GitHub Decided

Think of this as the master filing cabinet for the app's code. Every change ARC makes gets saved here first — it's the single source of truth, and it's what Netlify pulls from to publish updates.

Frontend Decided

The framework used to build Kiosk Compass and the CSAH App is React — a widely used, well-supported toolkit for building fast, interactive web apps. Both surfaces are built with it, which is part of why they can share code and components.

Netlify Decided

The hosting service — it takes the code from GitHub and makes it live on the internet, at no cost for CSAH's expected traffic. See the Hosting comparison doc for why this was chosen.

Maps Provider Provider TBD

Powers the maps embedded in the app — showing shelter, meal, and service locations, and giving directions. This is a separate service the app pulls map data from; it hasn't been decided yet whether that's a paid option like Google Maps or a free alternative like OpenStreetMap. See the Monthly Costs doc for the cost tradeoffs.

Cellular Provider Provider TBD

The kiosks are outdoor, standalone units — they need their own internet connection to reach Netlify and Supabase, so each one needs a cellular data plan (like a SIM card in a phone). This is separate from the CSAH App, which runs on staff devices that already have their own connectivity. See the Kiosk Connectivity doc for the options being weighed.

Supabase Decided

The shared database behind both Kiosk Compass and the CSAH App. One source of data means a shelter's hours only ever need to be updated in one place, and both surfaces stay in sync automatically. It also handles staff login for the CSAH App — see Auth below.

Auth (Login) Decided

Staff login for the CSAH App is handled by Supabase Auth — it's built into the same Supabase system that runs the database, not a separate service. Kiosk Compass doesn't need this at all; it's public, no login required.

SMS Message Alerts Provider TBD

When someone at a kiosk requests help, an SMS message goes out to the CSAH outreach team so they know to respond. The texting provider hasn't been locked in yet.

Push Notifications Details TBD

Inside the CSAH App, staff get real-time push notifications for crisis coordination and case updates — the same way a texting app pings you, but built into the CSAH App itself.

What's not locked in yet

  • Analytics- tbd Plausable or is what's provided by vendor sufficient?
  • Kiosk lockdown/MDM software — see the Kiosk Software comparison doc
  • Domain/DNS — subdomain of homelessauthority.org vs. a new domain, still open per the Hosting doc
  • Translation Architecture- leaning towards I18N self define to keep costs down and it's simple nature
