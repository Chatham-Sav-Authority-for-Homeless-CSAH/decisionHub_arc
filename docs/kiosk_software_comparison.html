Kiosk Software Comparison

Compass Project — evaluated against ARC project requirements

What ARC is actually building here — and what it isn't ARC does not build any device-monitoring, lockdown, or MDM software. That layer is always a bought product, never something ARC engineers. It comes from one of two places: bundled with the hardware (MetroClick's own SaaS platform is the example on this page), where CSAH pays the kiosk vendor and it's their product — or a separately licensed third-party MDM (SiteKiosk, Scalefusion, KioWare), where CSAH pays that company and "ARC installs" just means configuring the subscription (pointing it at the kiosk's URL, setting lockdown rules), the same kind of setup work you'd do for any SaaS tool, not software development. Either way, the app itself doesn't know or care which one is running underneath it — it's just a website, and the MDM layer's whole job is to lock a browser to that website's URL. Zero code dependency, zero build effort on ARC's side, regardless of which option CSAH ends up paying for. This page is a procurement/cost comparison, not an engineering decision.
How these platforms work All four options lock a device to a URL — the kiosk and the partner app read from the same backend automatically since both are built on a shared API (see ADR-004). Single data source and on-demand content updates are solved at the architecture layer, not by the kiosk software. The differentiators are: how well each manages a remote fleet, how much accessibility tooling is built in for public-facing use, and whether the platform is hardware-agnostic.
Push and SMS notifications Kiosk-triggered notifications (e.g. a user requests a caseworker) are handled by the web app running on the kiosk — not by the kiosk software itself. All four platforms are equivalent here. This is an app architecture decision, not a kiosk software decision.

Verdict
Summary Solid, mature lockdown with the strongest accessibility story via JAWS — but JAWS is a separate, costly license. Weakest on API-driven data sharing. No device minimum is a real advantage at small scale. Enterprise tier covers both Windows and Linux at the same rate: $195/device/yr license + 20% for Remote Management and Device Support = $234/device/yr. Purpose-built for public-facing web kiosks, not MDM retrofitted. Built-in CMS and strong API align with the single-data-source requirement; touch-first design suits the unhoused population. No confirmed Linux support. Nonprofit discount eligibility is still unconfirmed — but support and updates are included with no separate add-on. No device minimum. Strongest hardware flexibility, best-in-class remote fleet mgmt, and deep kiosk lockdown — the right call if hardware ever changes. MDM-first means accessibility shifts entirely to the app layer. Linux requires the pricier Business tier. Own hardware and software, tightly integrated. No third-party lockdown/MDM stack to assemble, top or tied-top on every fit category, and the only column backed by a signed quote. Free accessibility beats KioWare's paid JAWS. The tradeoff is cost, not capability — you're paying for integration, not a weaker product.

Scores reflect fit to Compass Project requirements only — not general-purpose rankings.
